# tenth-man

[Codex](https://developers.openai.com/codex) と [Claude Code](https://claude.com/claude-code) で使える、複数モデルによる意思決定のプラグイン（スキルと席のエージェント）です。設計判断や方針の見直しなど、1 つのモデルの答えだけで決めたくない議題に使います。モデルの違う複数の席が票を入れ、決まった 1 席が必ず反論するので、全員が同じ見落としをしたまま合意することを減らせます。

[English](README.md)

複数の参加者が各案に投票し、別の **10 番目の男** が、自分の見解にかかわらず全案に反論します。反論には必ず、それを崩せる証拠や実験も添えます。メインのセッションが議長となって 3 ラウンドを進め、強い懸念を解消し、何がどんな根拠で決まり、何が未解決かを議事録に残します。

スキルは必ず先に会議案を示し、ユーザーの了承を待ちます。会議を実行しても、結論がプロジェクトへ自動で反映されることはありません。

## 会議の進み方

1. 議長が、項目・モデル・規則・実行回数・出力フォルダを提案します。
2. 第 1 ラウンド: 参加者が投票し、10 番目の男が全項目に反論します。
3. 第 2 ラウンド: 強い懸念を再検討し、重要な反論に答えます。
4. 第 3 ラウンド: 議事録案に最終投票し、10 番目の男が根拠との食い違いを確認します。
5. 議長が `.tenth-man/<日付>-<短い名前>/minutes.md` を書きます。

票は **賛成**、**条件付き賛成**、**反対**、**強い懸念** の 4 種類です。参加者の過半数が賛成または条件付き賛成で、強い懸念が残っていない場合だけ合意になります。10 番目の男には票がありません。

## Codex への導入

### プラグインとして

```sh
codex plugin marketplace add <owner>/tenth-man
codex plugin add tenth-man@tenth-man
```

`<owner>` は、このリポジトリを置いた GitHub アカウントに置き換えてください。手元のチェックアウトを試す場合は、そのパスを登録します。

```sh
codex plugin marketplace add /path/to/tenth-man
codex plugin add tenth-man@tenth-man
```

プラグイン版は `$tenth-man:council` に続けて議題を書くか、`/skills` から選びます。

```text
$tenth-man:council セッションの状態を Redis から署名付きクッキーに移すべきか？
```

### 単独のスキルとして

`skills/council` を Codex のスキルフォルダへコピーします。

```sh
cp -r skills/council ~/.agents/skills/
```

この方法で入れた場合は `$council` で呼び出します。

1 つのリポジトリだけで使う場合は `<repo>/.agents/skills/` に置きます。このリポジトリの `.codex/agents/` には、役割を固定していない Codex 用の席定義も入っています。チェックアウト内では自動で見つかり、すべてのリポジトリで使う場合は次のようにコピーします。

```sh
cp .codex/agents/seat-*.toml ~/.codex/agents/
```

このコピーをしなくても、スキル自身が各サブエージェントへ同じモデルを直接指定し、次のラウンドでも同じスレッドを使うため、会議は動きます。プラグインとして入れても、カスタムエージェントの TOML が自動で入るとは限りません。

## Claude Code への導入

### プラグインとして

```text
/plugin marketplace add <owner>/tenth-man
/plugin install tenth-man@tenth-man
```

手元のチェックアウトを試す場合:

```sh
claude --plugin-dir /path/to/tenth-man
```

呼び出し方:

```text
/tenth-man:council セッションの状態を Redis から署名付きクッキーに移すべきか？
```

### 手で入れる

```sh
cp -r skills/council ~/.claude/skills/
cp agents/seat-*.md ~/.claude/agents/
```

この場合のコマンドは `/council` で、席の名前には `tenth-man:` が付きません。

## モデルのプリセット

小さい議題には `light`、それ以外には `standard` を議長が提案します。会議案を了承するときに、プリセットや席を変更できます。

10 番目の男には、参加者のうち推論の最も強いモデルと同じものを使います。強さの順は実際に使った結果で決めたもので、版の番号からは決めません。下の表の 10 番目の男は 2026 年 10 月時点の順位によるものです。新しいモデルが出て順位が分からないときは、議長がユーザーに聞きます。別のモデルにしたいときは、了承のときに指定してください。

### Codex

| プリセット | 投票する参加者 | 10 番目の男 | 1 ラウンドの実行数 |
|---|---|---|---|
| `light` | GPT-6 Astra、GPT-6.1 Sol、GPT-6.1 Terra | GPT-6 Astra | 4 |
| `standard` | GPT-6 Astra、GPT-6.1 Sol、GPT-6.1 Terra、GPT-6 Sol | GPT-6 Astra | 5 |
| `no-astra` | GPT-6.1 Sol、GPT-6.1 Terra、GPT-6 Sol | GPT-6.1 Sol | 4 |

現在の Codex とアカウントが提供するモデルだけを使います。使えないモデルは会議案で報告し、黙って別のモデルへ替えません。同時実行枠が席数より少ない場合は、同じ依頼文のまま数回に分けて起動し、全席が終わるまで集計しません。

対応する Codex のカスタムエージェントは `seat_astra`、`seat_sol`、`seat_terra`、`seat_previous_sol` と、任意の低コスト席 `seat_luna` です。TOML でモデルと推論強度を固定し、会議中の作業を読み取り専用に制限します。

### Claude Code

| プリセット | 投票する参加者 | 10 番目の男 | 1 ラウンドの実行数 |
|---|---|---|---|
| `light` | Fable、Opus、Sonnet | Fable | 4 |
| `standard` | Fable、Opus、Sonnet、Opus 5、Opus 4.8 | Fable | 6 |
| `no-fable` | Opus、Sonnet、Opus 5 | Opus | 4 |

Opus は Fable が見落とした問題を見つけることがあるので、Fable が上の時期でも、どのプリセットにも Opus の席を入れています。

Claude 用プラグインには、役割を固定していない 5 つの席が `agents/` に入っています。参加者か 10 番目の男かはラウンドの依頼文で指定します。

### Claude のモデルを足す

前の世代の Claude モデルは、エージェント定義の `model:` で選べます。席のファイルをコピーし、`name`、`description`、`model` を変えます。

```markdown
---
name: seat-opus-4-7
description: A seat in a tenth-man council, on Opus 4.7.
model: claude-opus-4-7
effort: high
tools: Read, Grep, Glob, Bash, Write
---
```

本文は同梱の席と同じ、役割を固定しない内容にします。すべてのプロジェクトで使うなら `~/.claude/agents/`、1 つのプロジェクトだけなら `.claude/agents/` に置きます。

### 手持ちの Claude エージェントを使う

手元にあるほかの Claude エージェント定義も席に着かせられます。議長は、今回はいつもの仕事ではなく会議の 1 席を務めると最初に伝え、共通の依頼文と役割を渡します。前の世代に固定したレビュー用エージェントがある場合に便利です。

### 固定した Claude モデルの提供が終わったら

固定したモデルが提供されなくなると、その席は起動に失敗します。議長は席を外したことを伝え、黙って別のモデルへ替えません。使えるモデルに合わせて席ファイルを削除または更新してください。

## 費用と前提

1 席は 1 ラウンドにつきサブエージェントを 1 回使います。3 ラウンドなら、Codex の `standard` は 15 回、Claude Code の `standard` は 18 回です。

- Codex: サブエージェントが有効な現行版と、選んだモデルへのアクセス。
- Claude Code: Agent、SendMessage、バックグラウンドエージェントの完了通知と、選んだモデルへのアクセス。

ChatGPT の通常チャットでは、席ごとに別のモデルのサブエージェントを動かせないため、現時点では対象外です。

## 名前の由来

映画『ワールド・ウォー Z』（2013 年）に登場したイスラエルの架空の規則、「10 番目の男」に着想を受けています。この規則では、9 人が同じ情報から同じ結論を出したとき、10 人目が反対の立場に立ち、9 人が間違っている前提で調べ直します。規則そのものは架空ですが、似た仕組みは実際にあります。

- イスラエル軍の情報部は、1973 年の第四次中東戦争で奇襲の兆候を読み違えたあと、アグラナット委員会の勧告を受けて、自分たちの評価にあえて異を唱える部署を置きました。この役目は、アラム語で「逆の方がありそうだ」を意味する *ipcha mistabra* と呼ばれます。
- タルムード（サンヘドリン篇 17a）には、死刑事件で裁判官の全員が有罪とした場合は被告を放免する、という規定があります。誰も被告の側に立たなかったなら、弁護の視点が検討されていないとみなすためです。
- カトリックの列聖審理には、候補者の生涯や奇跡の弱い点を探して反論する「悪魔の代弁者」という役がありました。1587 年に正式な役職になり、1983 年に大きく縮小されました。
