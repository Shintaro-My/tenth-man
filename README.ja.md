# tenth-man

[Codex](https://developers.openai.com/codex) と Claude（チャット、Cowork、[Claude Code](https://claude.com/claude-code)）で使用できる、複数モデルによる意思決定のプラグイン（スキルと席のエージェント）です。設計判断や方針の見直しなど、1 つのモデルの回答だけでは決定したくない議題に使用します。モデルの異なる複数の席が投票し、固定の 1 席が必ず反論するので、全員が同じ見落としをしたまま合意することを減らせます。

[English](README.md) | [日本語](README.ja.md) | [简体中文](README.zh-CN.md) | [繁體中文](README.zh-TW.md) | [한국어](README.ko.md) | [Español](README.es.md) | [Português (Brasil)](README.pt-BR.md) | [Deutsch](README.de.md) | [Français](README.fr.md)

複数の参加者が各案に投票し、別の **10 番目の男** が自分の見解にかかわらず全案に反論します。反論には必ず、その反証となる証拠や実験も添えます。メインのセッションが議長となって 3 ラウンドを進行し、強い懸念を解消します。議事録には合意の内容と根拠、未解決の点を記録します。

スキルは先に会議案を提示し、ユーザーの了承を待ちます。待たずに進めたいときは、議題の前に `fast` を付けます（例: `/tenth-man:council fast セッションの状態を移すべきか？`）。この場合、議長は会議案を提示した直後に会議を開始します。了承のときに決定するはずだった事項は既定の方法で決定し、議事録に記録します。会議を実行しても、結論がプロジェクトへ自動で反映されることはありません。

すでにある下書き（計画・設計書・文書など）を確認したいときは、下書きの前に `review` を付けます（例: `/tenth-man:council review docs/migration-plan.md`）。この場合は以下の順序で進行します。

1. 10 番目の男が下書きを読んで反論を出します。
2. 参加者が反論ごとに成立するかを判断し、修正案を示します。
3. 10 番目の男が再度反論します。
4. 参加者が最終投票をします。

議事録には認められた反論と修正案・却下された反論・未解決の点を記録します。認められた反論が 1 つもない結果も正常な結果です。各席の実行は 2 回なので、通常の会議より実行数は少なくなります。

## 会議の進行

1. 議長が、項目・モデル・規則・実行回数・出力フォルダを提案します。
2. 第 1 ラウンド: 参加者が投票し、10 番目の男が全項目に反論します。
3. 第 2 ラウンド: 強い懸念を再検討し、重要な反論に回答します。
4. 第 3 ラウンド: 議事録案に最終投票し、10 番目の男が根拠との食い違いを確認します。
5. 議長が `.tenth-man/<日付>-<短い名前>/minutes.md` を作成します。

票は **賛成**・**条件付き賛成**・**反対**・**強い懸念** の 4 種類です。参加者の過半数が賛成または条件付き賛成で、強い懸念が残っていない場合だけ合意になります。10 番目の男には票がありません。

## Codex への導入

### プラグインとして

```sh
codex plugin marketplace add Shintaro-My/tenth-man
codex plugin add tenth-man@tenth-man
```

手元のチェックアウトを試す場合は、そのパスを登録します。

```sh
codex plugin marketplace add /path/to/tenth-man
codex plugin add tenth-man@tenth-man
```

プラグイン版では、`$tenth-man:council` に続けて議題を入力するか、`/skills` から選択します。

```text
$tenth-man:council セッションの状態を Redis から署名付きクッキーに移すべきか？
```

### 単独のスキルとして

`skills/council` を Codex のスキルフォルダへコピーします。

```sh
cp -r skills/council ~/.agents/skills/
```

この方法で導入した場合は `$council` で呼び出します。

1 つのリポジトリだけで使用する場合は `<repo>/.agents/skills/` に配置します。このリポジトリの `.codex/agents/` には、役割を固定していない Codex 用の席定義も含まれています。チェックアウト内では Codex が自動で検出します。すべてのリポジトリで使用する場合は、以下のようにコピーします。

```sh
cp .codex/agents/seat-*.toml ~/.codex/agents/
```

このコピーをしなくても会議は実行できます。スキル自身が各サブエージェントへ同じモデルを直接指定し、次のラウンドでも同じスレッドを使用するためです。プラグインとして導入しても、カスタムエージェントの TOML が自動で導入されるとは限りません。

## Claude への導入

### Claude アプリから

ブラウザ版またはデスクトップアプリの Claude で、設定の「プラグイン」を開き、「追加」から「マーケットプレイスを追加」を選択して、以下の URL を入力します。

```text
https://github.com/Shintaro-My/tenth-man/tree/main
```

追加すると、「追加したマーケットプレイスから」の一覧に Tenth man が表示されます。この方法で追加したプラグインは、Claude のチャット・Cowork・Claude Code のどれでも使用できます。会議を開始するには、`/tenth-man:council` に続けて議題を入力するか、会議の開催を文章で依頼します。

### Claude Code の CLI から

```text
/plugin marketplace add Shintaro-My/tenth-man
/plugin install tenth-man@tenth-man
```

手元のチェックアウトを試す場合:

```sh
claude --plugin-dir /path/to/tenth-man
```

呼び出し方:

```text
/tenth-man:council セッションの状態を Redis から署名付きクッキーに移すべきか？
```

### 手動で導入する

```sh
cp -r skills/council ~/.claude/skills/
cp agents/seat-*.md ~/.claude/agents/
```

この場合のコマンドは `/council` で、席の名前には `tenth-man:` が付きません。

## モデルのプリセット

小さい議題には `light`、それ以外には `standard` を議長が提案します。会議案を了承するときに、プリセットや席を変更できます。

10 番目の男には、参加者のうち推論能力の最も高いモデルと同じモデルを使用します。この順位は実際に使用した結果に基づくもので、バージョン番号からは判断しません。下の表の 10 番目の男は 2026 年 10 月時点の順位によるものです。新しいモデルが公開されて順位が不明なときは、議長がユーザーに確認します。別のモデルにしたいときは、了承のときに指定してください。

### Codex

| プリセット | 投票する参加者 | 10 番目の男 | 1 ラウンドの実行数 |
|---|---|---|---|
| `light` | GPT-6 Astra、GPT-6.1 Sol、GPT-6.1 Terra | GPT-6 Astra | 4 |
| `standard` | GPT-6 Astra、GPT-6.1 Sol、GPT-6.1 Terra、GPT-6 Sol | GPT-6 Astra | 5 |
| `no-astra` | GPT-6.1 Sol、GPT-6.1 Terra、GPT-6 Sol | GPT-6.1 Sol | 4 |

現在の Codex とアカウントが提供するモデルだけを使用します。使用できないモデルは会議案で報告し、無断で別のモデルに変更することはありません。同時実行枠が席数より少ない場合は、同じ依頼文のまま数回に分けて起動し、全席が完了するまで集計しません。

対応する Codex のカスタムエージェントは `seat_astra`、`seat_sol`、`seat_terra`、`seat_previous_sol` と、任意の低コスト席 `seat_luna` です。TOML でモデルと推論強度を固定し、会議中の作業を読み取り専用に制限します。

### Claude

| プリセット | 投票する参加者 | 10 番目の男 | 1 ラウンドの実行数 |
|---|---|---|---|
| `light` | Fable、Opus、Sonnet | Fable | 4 |
| `standard` | Fable、Opus、Sonnet、Opus 5、Opus 4.8 | Fable | 6 |
| `no-fable` | Opus、Sonnet、Opus 5 | Opus | 4 |

Opus は Fable が見落とした問題を検出することがあります。そのため、Fable の順位が上の時期でも、どのプリセットにも Opus の席を含めています。

Claude 用プラグインには、役割を固定していない 6 つの席が `agents/` に含まれています。参加者か 10 番目の男かはラウンドの依頼文で指定します。

2026 年 11 月時点で、Fable は Fable 5.2 を指します。推論能力の最も高い参加者であることは変わりません。`seat-fable-5-1` は前の世代の Fable 5.1 に固定した席です。どのプリセットにも含まれていないので、参加者に追加したいときは、会議案を了承するときに指定してください。

### Claude のモデルを追加する

前の世代の Claude モデルは、エージェント定義の `model:` で選択できます。席のファイルをコピーし、`name`・`description`・`model` を変更します。

```markdown
---
name: seat-opus-4-7
description: A seat in a tenth-man council, on Opus 4.7.
model: claude-opus-4-7
effort: high
tools: Read, Grep, Glob, Bash, Write
---
```

本文は同梱の席と同じ、役割を固定しない内容にします。すべてのプロジェクトで使用するなら `~/.claude/agents/`、1 つのプロジェクトだけなら `.claude/agents/` に配置します。

### 既存の Claude エージェントを使用する

既存のほかの Claude エージェント定義も、会議の席に割り当てられます。議長は最初に、今回は通常の作業ではなく会議の 1 席を担当すると伝えます。そのうえで、共通の依頼文と役割を渡します。前の世代に固定したレビュー用エージェントがある場合に便利です。

### 固定した Claude モデルの提供が終了したとき

固定したモデルの提供が終了すると、その席は起動に失敗します。議長はその席を除外したことを伝え、無断で別のモデルに変更することはありません。使用できるモデルに合わせて、席のファイルを削除または更新してください。

## 費用と前提

1 席は 1 ラウンドにつきサブエージェントを 1 回実行します。3 ラウンドなら、Codex の `standard` は 15 回、Claude の `standard` は 18 回です。

- Codex: サブエージェントが有効な現行版と、選択したモデルへのアクセス。
- Claude（チャット、Cowork、Claude Code）: Agent、SendMessage、バックグラウンドエージェントの完了通知と、選択したモデルへのアクセス。これらがない環境では、会議を実行できないことをスキルが伝えます。

ChatGPT の通常チャットでは、席ごとに別のモデルのサブエージェントを実行できないため、現時点では対象外です。

## 名前の由来

映画『ワールド・ウォー Z』（2013 年）に登場したイスラエルの架空の規則「10 番目の男」に着想を受けて作成されたスキルです。この規則では 9 人が同じ情報から同じ結論を出したとき、10 人目が反対の立場に立ち、9 人が間違っている前提で再調査します。規則そのものは架空ですが、似た仕組みは実在します。

- イスラエル軍の情報部は 1973 年の第四次中東戦争で奇襲の兆候を読み違えました。その後アグラナット委員会の勧告を受けて、自分たちの評価にあえて異議を唱える部署を設置しました。この役割はアラム語で「逆の方がありそうだ」を意味する *ipcha mistabra* と呼ばれます。
- タルムード（サンヘドリン篇 17a）には、死刑事件で裁判官の全員が有罪とした場合は被告を放免する、という規定があります。誰も被告の側に立たなかったなら、弁護の視点が検討されていないとみなすためです。
- カトリックの列聖審理には、候補者の生涯や奇跡の弱い点を探して反論する「悪魔の代弁者」という役がありました。1587 年に正式な役職になり、1983 年に大きく縮小されました。
